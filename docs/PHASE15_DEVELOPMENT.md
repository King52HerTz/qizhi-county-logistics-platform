# 第十五阶段开发文档：空间数据治理与真实位置校准

## 1. 阶段目标

本阶段将网点坐标从“前端临时显示数据”升级为可审计、可核验、可长期维护的业务主数据，解决地图标点与真实位置不一致、坐标系混用、地图区域过小以及坐标修改无法追溯的问题。

交付范围：

- 建立 GCJ-02 展示坐标与 WGS-84 存储坐标的明确边界。
- 建立网点坐标状态、来源、精度、核验人和核验时间字段。
- 建立坐标修订历史和操作审计。
- 新增独立的空间数据校准工作台。
- 支持高德地图选点、地址反查、县域边界、异常标记和地图范围适配。
- 高德地图不可用时保留离线坐标校准能力。
- 为后续 PostGIS 空间查询、路网距离矩阵和动态事件定位提供可信坐标。

## 2. 坐标规范

| 数据用途 | 坐标系 | 说明 |
| --- | --- | --- |
| 高德地图显示、点击选点 | GCJ-02 | 与高德道路、POI 和行政区底图直接对应 |
| 数据库存储、空间交换 | WGS-84 | 用于标准空间数据交换和后续 PostGIS 分析 |
| 距离变化计算 | WGS-84/球面距离 | 使用 Haversine 米制距离，不以经纬度差值代替距离 |

系统禁止把 WGS-84 坐标直接作为高德地图标点，也禁止把 GCJ-02 坐标标记为 WGS-84。

## 3. 数据模型

### 3.1 logistics_nodes 扩展

- `wgs84_longitude`、`wgs84_latitude`：标准存储坐标。
- `coordinate_system`：当前固定为 `gcj02`。
- `coordinate_source`：`seed/imported/geocoded/manual`。
- `coordinate_status`：`unverified/needs_review/verified`。
- `coordinate_accuracy_m`：定位精度，单位米。
- `calibrated_at`、`calibrated_by`：最近核验信息。

### 3.2 node_coordinate_revisions

每次坐标修改保存：

- 修改前和修改后的 GCJ-02 坐标。
- 转换后的 WGS-84 坐标。
- 来源、状态、精度、地址和说明。
- 操作人和操作时间。

索引覆盖网点历史读取、核验状态筛选和操作人追溯。

## 4. 服务接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/master-data/spatial-quality` | 空间质量汇总 |
| `GET /api/v1/master-data/nodes?coordinate_status=...` | 按核验状态查询网点 |
| `PUT /api/v1/master-data/nodes/{id}/coordinate` | 保存校准坐标 |
| `GET /api/v1/master-data/nodes/{id}/coordinate-revisions` | 查询校准历史 |

坐标保存必须经过调度员或管理员权限，并同步写入业务审计日志。

## 5. 空间质量规则

- 县域范围检查：当前采用祁东县业务边界包络框快速检查。
- 重复坐标检查：发现多个网点使用完全相同坐标时计入质量统计。
- 地址完整性检查：缺少详细地址的网点单独统计。
- 核验状态检查：新建或导入坐标默认需要核验。
- 普通网点档案直接修改坐标后，状态自动变为“待复核”，不能绕过校准流程。

后续阶段可将快速边界检查升级为 PostGIS `ST_Contains` 精确行政区多边形检查。

## 6. 前端交互

新增“基础数据 → 空间校准”：

- 顶部显示网点总数、已核验、待复核、范围异常。
- 左侧为可搜索、可筛选的网点队列。
- 中间为占据主要空间的高德道路地图和县域边界。
- 右侧为坐标、地址、来源、精度、偏移距离、说明和历史记录。
- “重新定位”进入地图点击选点状态。
- “保存并标记已核验”提交坐标、地址和历史。
- 高德连接不可用时自动使用离线县域坐标底图，不中断资料维护。

## 7. 视觉基线

本阶段界面概念稿：

- `docs/concepts/phase15-spatial-calibration.png`
- 真白工作面、浅灰应用背景、深绿色导航和 `#168653` 主色。
- 中央地图是页面主视觉，不使用小地图卡片。
- 使用琥珀色表示待复核、红色表示范围异常、绿色表示已核验。
- 控件、文本和状态均为代码原生实现，不把界面截图作为产品组件。

## 8. 测试与验收

- 单元测试：GCJ-02 转 WGS-84、Haversine 米制距离、县域范围判断。
- 接口测试：坐标保存、WGS-84 生成、历史记录、审计日志、质量汇总。
- 数据库测试：Alembic 从上一版本升级到当前版本。
- 前端测试：TypeScript 构建、高德在线与离线降级、选点保存、响应式布局。
- 浏览器验收：桌面端和移动端截图、控制台错误检查、概念稿一致性检查。

## 9. 完成标准

- 地图标点使用与高德一致的 GCJ-02 坐标。
- 每个已核验网点都有标准 WGS-84 坐标和校准历史。
- 坐标修改不会静默覆盖原数据。
- 地图完整显示县域边界和网点，选点后可保存并再次读取。
- 无高德连接时，基础校准流程仍可用。
