# 第七阶段开发任务：企业级平台壳层与 AI 集成管理

## 1. 阶段目标

第六阶段已完成算法证据闭环，但平台入口和系统设置仍偏竞赛演示。本阶段以企业后台的常规使用方式重构两条基础能力：

1. 所有业务页面统一经过登录门禁，身份失效后回到登录页；
2. AI 服务由“打开页面直接编辑单个配置”升级为“连接列表—新建/编辑—独立测试—启用/停用”的资源管理流程。

## 2. 开源产品参考

- Logto：参考统一身份入口、会话与角色边界；
- Open WebUI：参考多模型连接、启停状态和逐连接测试；
- Dify：参考设置页的列表、抽屉与渐进式配置；
- Infisical：参考密钥只写不读、集中管理和审计留痕。

本项目复用这些成熟交互模式，不复制其代码和视觉资产。

## 3. 登录与访问控制

- 登录页成为全局平台入口，不再把登录表单散落在系统设置等业务页面；
- 支持当前会话和“在此设备保持登录”两种浏览器存储方式；
- JWT 默认有效期由 8 小时收紧为 60 分钟；
- 连续 5 次密码错误锁定账号 15 分钟；
- 保存最近登录时间、IP、失败次数和锁定时间；
- 登录成功、登录失败、锁定拦截和退出均写入审计日志；
- 调度、预测、路网状态、场景与历史方案等业务接口均要求 JWT；
- 导航按角色隐藏管理员设置入口；API 仍执行服务端角色校验。

## 4. AI 连接管理

`ai_provider_configs` 新增：

- 配置名称与描述；
- 创建人、更新人和更新时间；
- 一个数据库级部分唯一索引，保证最多只有一个 `enabled=true`；
- 原有 API Key 密文、服务商、Base URL、模型、温度和最近测试结果继续保留。

新增接口：

- `GET /api/v1/ai/configs`：连接列表；
- `POST /api/v1/ai/configs`：新建连接，API Key 必填；
- `PUT /api/v1/ai/configs/{id}`：编辑连接，API Key 留空表示保留；
- `POST /api/v1/ai/configs/{id}/test`：测试指定连接，不要求先启用；
- `POST /api/v1/ai/configs/{id}/activate`：设为默认并停用其他连接；
- `POST /api/v1/ai/configs/{id}/disable`：停用连接。

旧版单配置接口暂时保留用于兼容，但前端不再使用。

## 5. 审计模型

新增 `audit_logs`，记录分类、动作、结果、资源、操作者、IP、User-Agent、结构化详情和时间。密钥明文、密码和令牌禁止进入审计详情。

当前已覆盖：

- 身份：登录成功、失败、锁定拦截、退出；
- AI 配置：新建、更新、测试、启用、停用。

下一阶段将增加可筛选的审计日志页面和安全策略管理页。

## 6. 前端交互

### 6.1 企业登录页

- 左侧呈现平台定位、能力与服务状态，右侧为清晰的账号登录；
- 密码可见性切换、表单禁用态、行内错误、锁定提示完整；
- 900px 以下切换为单栏移动布局；
- 视觉概念稿：`docs/concepts/phase7-enterprise-login.png`。

### 6.2 AI 服务连接页

- 默认只展示连接列表和状态摘要，不暴露编辑表单；
- 点击“新建连接”或“编辑”后打开右侧抽屉；
- API Key 仅在抽屉中输入，已保存连接只显示掩码；
- 测试、编辑、设为默认和停用均作用于指定连接；
- 视觉概念稿：`docs/concepts/phase7-ai-connections.png`。
