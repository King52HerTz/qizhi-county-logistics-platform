# 第五阶段开发任务：审批、下发与驾驶员执行闭环

## 阶段目标

将“算法生成路线”升级为“可审核、可下发、可接单、可完成、可追溯”的业务执行流程，使竞赛演示能够回答方案如何进入实际运营。

## P5-01 角色与权限

- `admin`：审批、驳回、下发、查看全部任务与报告。
- `dispatcher`：提交方案、下发已批准方案、查看执行状态。
- `driver`：只查看分配给自己的车辆任务，并进行接单、发车和完成确认。
- 所有写接口使用 JWT 身份校验；驾驶员不能审核方案或操作他人任务。

## P5-02 方案状态机

```text
pending_approval → approved → dispatched → accepted → executing → completed
                 ↘ rejected
```

- 不允许跳过审批直接下发。
- 不允许重复审批、重复接单或越级完成。
- 同一求解方案只生成一个执行单。
- 每次状态变化写入不可变审计日志。

## P5-03 驾驶员任务

- 已批准方案下发时，按求解路线创建独立车辆任务。
- 任务保留车辆、里程、载重、停靠点、预计耗时和原始路线快照。
- 驾驶员按 `pending → accepted → executing → completed` 更新。
- 执行单状态由所有车辆任务汇总计算，不由前端直接修改。

## P5-04 执行中心

- 新增统一“执行中心”入口。
- 管理员视图展示批次、状态流程、车辆任务和操作入口。
- 驾驶员视图展示下一站、里程、载重、停靠数与状态按钮。
- 支持导出自包含 HTML 执行报告，可直接使用浏览器打印为 PDF。

## P5-05 验收

- 越权审批返回 403。
- 非法状态跳转返回 409。
- 下发后任务数量与求解路线数量一致。
- 所有驾驶员任务完成后，执行单自动变为 `completed`。
- PostgreSQL 迁移、自动化测试、生产构建、Docker 与浏览器流程全部通过。

## 演示账号

