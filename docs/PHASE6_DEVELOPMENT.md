# 第六阶段开发任务：竞赛证据与算法实验室

## 1. 阶段目标

第五阶段已经打通“求解—审批—下发—驾驶员执行”。第六阶段补齐竞赛答辩需要的证据链：在固定输入与固定口径下重复运行压力案例，量化 OR-Tools 相对日常业务基线的里程、成本、运力和服务率变化，并让每次结果可查询、可复跑、可导出。

## 2. 实验口径

| 案例 | 货量规则 | 验证重点 |
|---|---|---|
| 标准负荷 | 原始订单 | 正常运营收益 |
| 旺季峰值 | 全部订单 × 1.18 | 峰值运力弹性 |
| 冷链压力 | 冷链 × 1.22，常温 × 1.08 | 冷链兼容与运力约束 |

业务基线为确定性轮询启发式，执行容量、冷链、时间窗和班次校验；OR-Tools 使用相同场景和道路矩阵。业务基线用于代表未优化的固定调度策略，不宣称数学最优。

## 3. 数据设计

`algorithm_experiments` 使用顺序整数主键，保存：

- 实验编号、名称和状态；
- 场景版本外键、版本键和 SHA-256 指纹；
- 求解器、业务基线和单案例时限；
- 聚合摘要与逐案例 JSON 结果；
- 创建人、创建时间、完成时间和失败消息。

场景外键、创建人以及常用的状态/场景时间筛选均有索引；状态、时限和案例数使用数据库约束。

## 4. API

- `POST /api/v1/experiments`：同步运行三压力实验并持久化。
- `GET /api/v1/experiments`：实验历史。
- `GET /api/v1/experiments/{id}`：实验详情。
- `GET /api/v1/experiments/{id}/report`：自包含 HTML 报告。

## 5. 前端

新增“算法实验”导航和算法对照实验室，页面包含：

- 平均里程降低、累计成本差额（正值为节省、负值为增加）、订单服务率和实验编号；
- 业务基线/OR-Tools 柱状图与里程降低折线；
- 场景版本、求解器、时限和指纹配置区；
- 三压力案例结果表；
- 最近实验历史与报告导出。

概念设计保存在 `docs/concepts/phase6-algorithm-lab.png`。
