# 第四阶段开发任务：路网增强与预测决策驾驶舱

## 阶段目标

将第三阶段的数据闭环升级为“需求预测—路网矩阵—约束求解—决策展示”的竞赛演示闭环。真实路网服务不可用时必须自动回退，任何预测结果都必须标注方法和数据边界。

## P4-01 路网矩阵服务

- 新增 OSRM Table API 适配器，同时读取距离（米）与时间（秒）。
- OR-Tools 继续使用整数米、整数分钟，容量、时间窗和冷链约束保持不变。
- 支持 `ROUTING_PROVIDER=osrm|haversine` 配置。
- OSRM 超时、不可达或返回异常时自动回退到 Haversine×县乡绕行系数。
- 求解响应公开请求源、实际数据源、缓存命中、回退状态和数据版本。
- 相同坐标矩阵使用进程内 LRU 缓存，容量可配置。

## P4-02 需求预测

- 提供 3–30 日需求预测接口。
- 当前竞赛数据使用四期加权移动平均与星期季节因子。
- 输出历史画像、预测上下界、乡镇需求排行、冷链需求、峰值日、风险等级和建议车辆数。
- 页面明确说明预测用于决策演示；接入连续真实订单后再替换为 LightGBM 分位数模型。

## P4-03 决策驾驶舱

- 新增“运营总览”入口和 1440×900 单屏驾驶舱。
- 顶部展示需求、运力、矩阵来源和准时率。
- 左侧展示七日需求趋势与乡镇排行。
- 中央复用县域路线地图，显示当前优化方案和矩阵来源。
- 右侧展示路网状态、缓存、运力建议和峰值风险。
- “生成今日调度”直接进入智能调度并重新求解。

## P4-04 验收标准

- OSRM 正常返回时使用非对称真实道路矩阵。
- 连续相同请求命中缓存，不重复请求 OSRM。
- OSRM 异常时求解不中断，响应明确标记回退。
- 预测接口的天数、上下界、排行和建议运力通过契约测试。
- 后端测试、前端生产构建、Docker 健康检查和浏览器核心流程全部通过。

## 配置示例

```dotenv
ROUTING_PROVIDER=osrm
OSRM_BASE_URL=https://router.project-osrm.org
OSRM_PROFILE=driving
OSRM_TIMEOUT_SECONDS=15
ROUTING_CACHE_SIZE=128
```

公共 OSRM 实例只适合开发验证。正式答辩或生产环境应部署自有 OSRM，并准备 `ROUTING_PROVIDER=haversine` 的离线兜底配置。

## 数据边界

- 当前预测的“近 7 日运营画像”由激活场景构造，不冒充企业真实历史订单。
- OSRM Table 提供道路距离与预计行驶时间，但当前地图仍以节点连线展示，不是司机导航级轨迹。
- 路况拥堵、天气和临时封路尚未作为实时权重输入。
